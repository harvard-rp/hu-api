The first integration iteration caught a row visibility error when a reviewer archived a sheet without reopening authority. PostgreSQL requires visibility of the updated row for `RETURNING`. The scoped role can return that row, while public archive and history operations still enforce their own capability boundary. The archive workflow test repeats this scenario using a reviewer without `characters.reopen` when the third refusal is recorded.

## Reproduction and limits

On a machine with a local Docker Engine, run `pnpm install --frozen-lockfile`, `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, then `pnpm supabase:start`, `pnpm supabase:reset`, `pnpm test:integration`, `pnpm test:auth:local`, `pnpm test:concurrency` and `pnpm supabase:types`. Check the types with `git diff --exit-code -- src/lib/supabase/database.types.ts` and stop the stack with `pnpm supabase:stop`. Set `HU_TEST_WORKER=1` for the Auth suite when a local Worker on `127.0.0.1:8787` points to the same local Supabase stack. The suite otherwise uses the normal in-process HTTP entry point. Run the [legacy rehearsal](CHARACTER_POLICY_MIGRATION.md#read-only-inventory-before-approval) on a separate disposable database.

Docker was unavailable for this run. The SQL, Auth, Data API and workerd checks used local binaries, and the Docker-specific CLI orchestration and hosted CI were not exercised. The Auth suite used fixture accounts in GoTrue. It did not exercise real Discord OAuth, provider document accessibility, or the forthcoming HU-009F-C UI. The [migration handoff](CHARACTER_POLICY_MIGRATION.md) and [policy](CHARACTER_POLICY.md#notifications-and-remaining-decisions) describe the remaining rollout and staff decisions.
